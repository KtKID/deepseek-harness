# Plugin Analyzer 独立发布规范修复报告

> 修复时间：2026-08-19 22:20
> 修复人：Codex (x-fix)

## Bug 描述

Plugin Analyzer 的实现位于 `packages/host/plugin-analyze`，缺少 Market 可安装的公开组合包，产品改名仍有遗漏，Web 内置组合与共享 Remote 组合还会默认加载该功能。这个结构无法提供完整安装、卸载和独立发布语义。

## 根因分析

仓库中的 `packages/host/` 与 `packages/client/` 存放运行时实现包；`packages/bundle/` 存放 `dsh plugin add` 与 profile patch 使用的公开安装目标。早期实现直接接入 `dsh-web-app` 和 `dsh-api-remotes`，因此功能归属在内置应用组合中。目录短名称匹配、Remote Fiber 作用域和 workspace 门禁登记又形成了三个独立缺陷。

## 修复方案

- 建立公开组合包 `packages/bundle/plugin-analyzer`，声明 `dsh.bundle.patch`、`cordis.patch.yml`、公开包元数据、许可证、发布文件与两个直接实现依赖。
- 把 Host 与 Client 实现统一命名为 `plugin-analyzer`，同步 npm 包名、service、组件、快照、路径、TypeScript 引用、生成目录和双语文档。
- 从 `dsh-web-app` 与 `dsh-api-remotes` 移除内置 Analyzer 组合，由选择启用的组合包插入 Host 与 Client Loader 条目。
- 由 Client 父 Fiber 挂载生成的 Remote 贡献，子 Fiber 注入 `remote.pluginAnalyzer` 并挂载 UI；清理时先释放 UI，再撤回 Remote namespace。
- 通过 npm 包名解析生成图归属，补充同名目录叶子的回归测试，并登记 bundle patch 与 Knip 的 patch 专用依赖。
- 新建严格任务清单与双语开发报告，记录已完成实现、验证证据和剩余发布阻塞项。

## 主要修改位置

| 路径 | 修改内容 |
|---|---|
| `packages/bundle/plugin-analyzer/` | Market/CLI 公开安装目标与两行 profile patch。 |
| `packages/host/plugin-analyzer/` | Host 数据采集、历史、Remote、配置与释放。 |
| `packages/client/ui-settings-plugin-analyzer/` | 设置 UI、Remote 贡献、本地化与生命周期。 |
| `packages/bundle/web-app/`、`packages/api/remotes/` | 删除 Analyzer 默认组合归属。 |
| `scripts/gen-doc-graphs.ts`、`scripts/check-workspace-constraints.ts`、`knip.json` | 修正生成归属并登记发布门禁。 |
| `dev-pipeline/tasks/plugin-analyzer-market-release/` | 市场发布任务清单与开发报告。 |
